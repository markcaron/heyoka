Image Performance Demo

Export a JPG at larger dimensions with lower quality. You get a smaller file that looks sharper than a smaller export at higher quality.

The Comparison

Export Dimensions Quality File Size
2500px, low quality 2500 × 1407 Low (~20–30%) 252 KB
1000px, high quality 1000 × 563 High (~80–90%) 621 KB

The 2500px export has 6.25× more pixels and weighs less than half the file size.

Why This Works

JPEG compression discards high-frequency detail: sharp edges, fine textures, subtle gradients. Lower quality settings discard more, which produces visible artifacts (banding, blockiness) at native resolution.

The browser hides those artifacts when it downscales the image to display size. Downsampling blends neighboring pixels together, smoothing over the blocky compression boundaries before you see them.

  1. Export at 2× or more of the display size. More source pixels give the browser more data to blend during the downscale.
  2. Drop JPEG quality to 20–30%. File size plummets because you're throwing away detail the downscale would have discarded anyway.
  3. Display at the intended size. The browser's downsampling acts as an anti-aliasing pass over the compression noise.

You end up with a sharp image at a fraction of the file size. Artifacts that show at 1:1 zoom disappear at display size.

When to Use This

  • Photographic content (landscapes, action shots, portraits) where organic texture masks compression noise
  • Hero images and backgrounds displayed at a fixed, smaller-than-source size
  • Pages that show the same image at multiple sizes (full view + thumbnail grid). One cached file serves both. The browser downloads it once and downsamples to each display size on the fly, instead of fetching separate assets per breakpoint.

When NOT to Use This

  • Images viewed at native resolution (lightboxes, pinch-to-zoom galleries)
  • Graphics with sharp text, lines, or flat color. Use PNG or SVG instead.

Modern Formats

WebP and AVIF handle low-quality compression better than JPEG. You get fewer visible artifacts at equivalent file sizes because their encoders allocate bits more intelligently around perceptual edges.

  • WebP (lossy). Baseline in all browsers since 2023. 25–35% smaller than equivalent-quality JPEG.
  • AVIF. Baseline in all browsers since late 2024. 40–50% smaller than JPEG. Encoding is slower.

The same large-dimensions-low-quality strategy applies to both. You can push quality lower than you would with JPEG before artifacts show at display size.
